# Frame Cropper

ページの中の**埋め込みコンテンツ (iframe / canvas) だけ**をウィンドウいっぱいに
表示する Firefox 拡張機能です。

ヘッダー・サイドバー・広告・下部バナーに囲まれた小さな枠でアプリが動いているページを、
**その枠だけの表示**に切り替えます。Alt+Shift+Z ひとつで ON / 候補送り / OFF が回り、
当たった枠はページごとに記憶されます。

素朴に実装すると壊れる点がいくつもあり、それぞれに対処しています。

- iframe は **DOM 上で動かすと中身が再読み込みされる**ので、位置合わせは CSS だけで行う
- `transform` を持つ祖先があると `position: fixed` がビューポート基準にならない
- 固定サイズで作られた中身は、CSS で拡大すると**クリック座標がズレる**。
  ブラウザのズーム (`tabs.setZoom`) を使えば座標系が一切崩れない
- 配信元が多段の**クロスオリジン入れ子フレーム**になっていることがあり、
  外側からは中を覗けない

詳しくは [設計の要点](#設計の要点) に書きました。

個人用に作ったものを公開しています。無保証です。

## インストール

### A. まず試す (再起動で消える)

1. Firefox で `about:debugging#/runtime/this-firefox`
2. 「**一時的なアドオンを読み込む**」→ このフォルダの `manifest.json` を選ぶ

### B. 常用する (署名して恒久インストール)

Firefox 製品版は未署名の拡張を入れられない。自分用なら AMO の **unlisted 署名**が使える。

```bash
npm install -g web-ext
web-ext sign --channel=unlisted --api-key=<JWT issuer> --api-secret=<JWT secret>
```

API キーは https://addons.mozilla.org/developers/addon/api/key/ で発行。
生成された `web-ext-artifacts/*.xpi` を `about:addons` にドラッグすれば恒久的に入る。

### C. 署名を回避する (Developer Edition / Nightly / ESR のみ)

`about:config` → `xpinstall.signatures.required` を `false`。製品版では効かない。

## 使い方

**覚えるのは Alt+Shift+Z ひとつだけ**。押すたびに状態が 1 周する:

```
OFF ─→ 候補1 ─→ 候補2 ─→ … ─→ 候補N ─→ OFF ─→ …
```

押すたびに画面上部へ `2/5  iframe#app 1136×640` のように現在地が出る
（切り抜いた枠より前面に出るので全画面中でも読める）。最後の候補では `(次で OFF)` と付く。
当たった枠は**ページごとに記憶され、次回は 1 押し目でそこに入る**。

| 操作 | 効果 |
|---|---|
| **Alt+Shift+Z** | ON(候補1) → 候補2 → … → OFF のループ |
| 画面隅のボタン | **設定済みページでは OFF の間も出ている**。アイコンが役割を示す — 四隅の括弧 = 開始 / × = 解除 |
| ツールバーのアイコン | 設定パネル（解除ボタン・候補一覧・各種設定） |
| Alt+Shift+X | 対象をクリックで直接指定（候補に出てこない時の保険） |
| Esc | 解除（最上位ページにフォーカスがある時のみ） |

抜けるのは画面隅のボタン（既定で右下に薄く表示、位置は設定で四隅から選べる）。
枠の中にフォーカスがある間は Esc がページまで届かないので、ボタンかツールバーが確実。

パネルの「このサイトを開いたら自動で切り抜く」を ON にすると、以降そのページでは
開いた瞬間から切り抜き状態で始まる。**中身が起動する前にフレームが最大サイズになる**ので、
起動時にしか画面サイズを読まない作りでも正しく拡大される。

### 対象の選び方

自動検出は「面積 × 手掛かり」のスコアで決める。手掛かりの内訳:

| 条件 | 倍率 |
|---|---|
| `game_frame` `stage` `unity` `cocos` `pixi` `phaser` 等を含む | ×6 |
| `game` `canvas` `player` を含む | ×2 |
| `ad` `banner` `promo` `recommend` `ranking` 等を含む | ×0.03 |
| 最初の一画面より下 (y > 1.5 画面) にある | ×0.3 |
| `allowfullscreen` を持つ | ×1.5 |
| 広告配信ホスト (doubleclick / googlesyndication 等) | 除外 |

スコアが気に入らない時は、パネルの「対象の選び方」を **DOM で最初の枠** か
**面積が最大の枠** に変えるか、Alt+Shift+Z で候補を送って当てる方が早い。

## 設定の保存単位

設定 (対象セレクタ / 表示のしかた / 自動適用) は**ページ単位**で保存される。
キーは `ホスト名 + パスの先頭 2 階層`:

```
example.com/app/alpha
example.com/app/beta
example.com          ← パスが無ければホスト名だけ
```

ホスト名だけをキーにすると、1 つのホストの下にぶら下がる別々のコンテンツが
同じ 1 件を奪い合い、「片方で表示モードを変えるともう片方も変わる」状態になる。
必要なモードは中身の作りによって違う (固定サイズなら `bzoom`、
自前でレターボックスを持つなら `fill`) ので、混ざると実害が出る。

内側フレームの対象はさらに `フレームのホスト名 + パス` で分けて持つ。
同じホストに別のフレームが複数ぶら下がる構成 (`/a/main.html` と `/a/sub/panel.html`)
があり、ホスト名だけでは取り違えるため。

## 保存済みサイトの管理

キーがページ単位になったぶん件数が増えるので、パネルの「**保存済みサイト**」で
中身の確認と削除ができる。各行に何が保存されているか (自動適用 / 表示のしかた /
対象セレクタ / 内側フレームの件数) が出て、右の × で 1 件ずつ消せる。
今開いているページの行には印が付く。

覚えたセレクタは Alt+Shift+Z で候補を送った時点でも保存されるので、
試しに押しただけのページも溜まる。不要なものはここで消す。

## うまく動かない時

1. **別の枠が選ばれる** → Alt+Shift+Z をもう一度押して次の候補へ。当たった枠は記憶される。
   候補に出てこない要素は Alt+Shift+X でクリック指定。
2. **正解を通り過ぎて OFF まで行った** → 記憶が最後の候補で上書きされている。
   もう一周するか、パネルの「対象の記憶を消す」で自動検出に戻す。
3. **中身が小さいまま** → パネルで「内側のフレームも引き伸ばす」を ON。
   それでも駄目なら「このサイトを開いたら自動で切り抜く」を ON にして**再読み込み**
   (起動時のサイズを見に行く作り向け)。
4. **画面が真っ黒になる** → 対象は見つかっているが、それが描画面ではない。
   対象には `box-shadow` で周囲を黒く塗るので、誤検出するとその階層が全面黒になる。
   まず「内側のフレームも引き伸ばす」を OFF にして切り分ける
   (これで直れば内側フレームの誤検出)。パネルの「検出候補の一覧」は**全フレーム分**を
   階層ごとに出し、内側フレームの候補もクリックで選び直せる。
5. **対象が一度も切り替わらない** → 引き伸ばした要素は 100vw×100vh になって
   面積が最大になり、以後の自動検出で勝ち続けてしまう (自己強化ラッチ)。
   対策として**引き伸ばす前の実寸を `WeakMap` に覚えて採点に使う**ので、
   後から本物の枠が現れれば乗り換わる。

「検出候補の一覧」は「JSON でコピー」で丸ごと貼り出せる。この出力は
**URL のクエリ文字列を落としてある** — 埋め込み元の URL にセッショントークンや
アカウントIDが載っていることがあり、そのまま貼ると認証情報を晒すことになる。
切り分けに要るのは配信元とパスだけなので、そこまでに削っている
([tools/inspect-frames.js](tools/inspect-frames.js) も同様)。

## 設計の要点

| 論点 | 採った方法 | 理由 |
|---|---|---|
| 枠の全画面化 | **CSS の `position:fixed` だけ**で行う | iframe を DOM 上で移動 (`appendChild`) すると中身が**再読み込み**され、状態が失われる。CSS なら再読み込みが起きない |
| 周囲を隠す | 対象自身に `box-shadow: 0 0 0 100vmax #000` を掛ける | 影は**要素自身の描画の一部**なので対象と同じ重ね順に入り、DOM を一切増やさずに「対象より下・他より上」の黒地が作れる。比率維持でレターボックス表示になった時、余白から後ろのページが透けるのをこれ 1 行で止める |
| 対象が決まるまでの黒地 | `<html>` 直下に黒い幕 (`#ffc-backdrop`) を 1 枚敷く | `<html>` の子なのでサイトのコンポーネントツリーに触れない。対象の隣にノードを挿す案は、React 製 SPA が再描画で見知らぬ子ノードを巻き込む危険があるので採らない |
| バナーの一瞬の表示 | 自動適用ONのページでは `document_start` で**先に黒幕を出す** | 対象が見つかるまでの間、周囲の要素を一度も描画させない |
| 枠の検出 | 面積 × 手掛かりのスコアで選ぶ + 広告ホストを除外 | SPA ではクラス名が変わるので、決め打ちセレクタは壊れる |
| 検出を外した時 | **Alt+Shift+Z の連打で候補を送る** (ON→候補2→…→OFF の 1 キーループ) | スコアの当て推量を詰めるより、押して確かめる方が速い。ショートカットも 1 つで済む |
| 周囲の描画漏れ | 対象が iframe の時だけ、祖先の兄弟要素を CSS セレクタで `display:none` | 黒幕だけだと極端に大きい `z-index` の広告が上に出る余地が残る。セレクタ規則なので SPA が後から足した要素にも自動で効く |
| 手動指定 | 要素ピッカー (Alt+Shift+X) が**全フレームで動き**、枠をクリックすると中へ降りて選択を続ける | クロスオリジンの枠は外から中を覗けない。選択そのものを `postMessage` で中へ渡す |
| 入れ子フレーム | `all_frames: true` で全フレームに同じ content script を入れ、深い階層も 100% に伸ばす | 配信元 → ゲートウェイ → コンテンツ本体、と 2〜3 段になっていることがある |

### `position: fixed` が効かない罠への対処

`transform` / `filter` / `contain` / `will-change` が付いた祖先があると、`position:fixed` の
基準枠 (containing block) がビューポートではなく**その祖先**になり、全画面化が効かない。
React 製 SPA では普通に起こるので、対象の祖先すべてに `.ffc-ancestor` を付けて
これらを `none` に上書きしている ([src/content.css](src/content.css))。

### ウィンドウのリサイズ追従

枠は `100vw/100vh` なので、ウィンドウを変えれば**枠の側は CSS だけで追従する**
(フィクスチャ実測: 1200×800 → 980×799 まで 3 段すべて追従、canvas も比率維持で再計算)。
追従しないのは**中身が最初に読んだ寸法を握ったまま**の場合で、こちらは
クロスオリジンなので `childWindow.dispatchEvent()` を直接呼べない。`postMessage` で
下へ中継し、受けた側のコンテントスクリプトが自分の `window` に `resize` を投げ直す。

**駆動するのは最上位フレームだけ**にしてある。これは設計上の肝で、各階層が自分の
タイマーで揺さぶると次のように発振が止まらなくなる:

```
最上位が枠を 1px 変更 → 中間フレームで resize 発火 → 中間も 200ms 後に自分を揺さぶる
  → 最深フレームで resize 発火 → 最深も…  (以下、各階層のタイマーが噛み合って永久に継続)
```

下層は中継メッセージを受けた時だけ反応する受動側に徹する。最上位の動作は 2 段階:

| 局面 | 動作 | 理由 |
|---|---|---|
| ドラッグ中 | 250ms ごとに下へ中継 | 毎フレーム中継すると 1 フレームに 3〜5 回レイアウトが走って震える |
| 停止 200ms 後 | 枠を `calc(100vw + 1px)` に 2 フレームだけ広げて戻す | 合成イベントを無視して実寸だけ見るエンジン (`ResizeObserver` 系) にも確実に届く。**縮めるのではなく広げる**のは、縮めると縁に 1px の黒線が一瞬出るため。`html { overflow: hidden }` なのではみ出し分は切り取られ、見た目には出ない |

### 表示のしかた 4 種

- **fill**: `width:100vw; height:100vh`。中身が自前でレターボックス処理を持つ場合はこれが正解。
- **fit**: 縦横比 `--ffc-ar` を使い
  `width: min(100vw, calc(100vh * var(--ffc-ar)))` で比率を保ったまま最大化。canvas を直接掴んだ時用。
- **bzoom** (ブラウザズーム): 要素は**元の実寸のまま**中央に置き、拡大は
  `tabs.setZoom()` でブラウザのズームに任せる。**固定サイズで作られた中身はこれが本命**。
  理由は座標系にある — 埋め込みアプリはよく次のように書く:

  ```js
  const rect  = canvas.getBoundingClientRect();
  const ratio = canvas.width / canvas.clientWidth;   // ここが要
  const x     = (e.clientX - rect.left) * ratio;
  ```

  `transform: scale()` を掛けると `getBoundingClientRect()` は**拡大後**、
  `clientWidth` は**拡大前**を返すので、この比が倍率ぶん狂い、左上は合うのに
  右下ほどズレる。ブラウザズームは CSS ピクセルの定義自体を変えるため
  **両方とも同じ単位のまま**で、中身の計算が一切崩れない。

  倍率は `(ビューポートのCSS幅 × 現在の倍率)` を基準に出す。この値はズームを
  変えても不変なので、ズーム→resize→再計算 が一発で収束する。
  Firefox は倍率を小数 2 桁に丸めるので、こちらも 2 桁に量子化した上で
  ±0.02 の不感帯を置く (置かないと丸め差で 2 値を往復し続ける)。
  `scope: 'per-tab'` にしてサイトの既定ズームを汚さず、解除時に元の倍率へ戻す。

  **解除経路は 4 つあり、全部で復元する必要がある**: Alt+Shift+Z のループ OFF /
  画面隅のボタン / Esc / パネルの解除ボタン・別ページへの移動。
  復元処理では `setZoomSettings` と `setZoom` を**別々の try に分ける** —
  ひとつにまとめると scope 戻しに失敗した時点で肝心の倍率復元が実行されないまま
  握りつぶされ、ズームが掛かりっぱなしで残る。
- **zoom** (拡大変換): `transform: scale()` で拡大する。中の座標系は保たれ、
  CSS 変換は当たり判定にも適用されるのでクリック位置もずれない。ただし上記のとおり
  `clientWidth` を使う中身とは相性が悪い。
- **auto** (既定): iframe なら fill、canvas/video なら fit、**div など通常要素なら bzoom**。

**iframe には拡大系モード (zoom / bzoom) を適用しない。** iframe は「器」で、中身を
見せるには広げるのが常に正しい。モード設定はページ単位なので、ここを分けないと
「canvas を bzoom にしたら上位の iframe まで自然サイズに戻り、ズーム倍率が
0.41 に化ける」という壊れ方をする。

### 実測 (フィクスチャ、canvas 1280×720 / ビューポート 1398×1270)

| モード | 表示サイズ | `clientWidth` | `rect.width` と一致 |
|---|---|---|---|
| fill | 1398×1270 | 1398 | ✓ |
| fit | 1398×786 | 1398 | ✓ |
| zoom | 1398×786 | **1280** | **✗ (ここが座標ズレの正体)** |
| bzoom | 1280×720 (無変更) | 1280 | ✓ |

**スケーリングを一切考慮していない中身** (`x = clientX - rect.left` で終わり、
比率補正を掛けない) は、CSS で大きさを変えるどの方式でも壊れる。
固定サイズでしか表示されない前提で作られていれば普通にあり得る。
この場合、**ブラウザズームだけが唯一の解**になる — 要素の CSS サイズを
保ったまま、描画だけが拡大されるため。

縦横比の取り方: canvas は**表示サイズではなく描画解像度** (`width`/`height` 属性) から取る。
表示サイズは拡張自身が変えてしまうので基準にならない。さらに `MutationObserver` で
その 2 属性を監視し、中身が解像度を変えたら比率を取り直す
(切り抜いた瞬間の比率で固定されて、それ以上伸びなくなるのを防ぐ)。

### 同じ指示を撒き直さない

background は「後から生えるフレームに届ける」ため、適用後 300〜8000ms に同じ指示を
5 回送る。受け取った側が毎回 `clearMarks()` → 再採寸 → 再適用すると、その都度
枠が素の寸法に戻ってから切り抜き寸法に戻る reflow が起きて画面がガタつく
(bzoom ではズーム再計算まで巻き込む)。指示の署名を比較して、同じなら何もしない。

## 動作確認 (実サイトに触れずに試す)

[tools/fixture.html](tools/fixture.html) は、実サイトでよくある罠をわざと全部盛りにした
テストページ。拡張を読み込んだ Firefox でこのファイルを開き、Alt+Shift+Z を押す。

- `transform: translateZ(0)` を持つ祖先 (基準枠の罠)
- `opacity: 0.999` を持つ祖先 (重ね順の罠)
- `z-index: 99999` の sticky ヘッダー / `z-index: 2147483000` の固定バナー
- iframe → iframe → canvas の 3 段入れ子
- canvas の兄弟に置かれた可視要素 (レターボックスの余白から透ける罠)

このフィクスチャでの実測結果:

| 確認項目 | 結果 |
|---|---|
| 最上位 iframe がビューポートと一致 | 640×360 → **1398×1270 (0,0)** 完全一致 |
| 画面中央・左下の最前面要素 | どちらも対象の iframe (バナー類は `display:none`) |
| 中間フレーム内の iframe | **1398×1270** に追従 |
| 最深部の canvas (比率維持) | 960×540 → **1398×786**、比率 1.7778 を保持しレターボックス |
| レターボックスの余白 | canvas の兄弟に置いた白い要素が**完全に隠れる** |
| ウィンドウ変更後 | 1200×800 → 980×799 まで 3 段すべて追従 |
| 解除後 | 640×360 (y=67) に復元・ヘッダー/バナー復帰・残留ノード 0 |

## ファイル構成

```
manifest.json          MV2。Firefox は MV2 を維持しており、host_permissions の
                       ユーザー承認待ちが無いぶん MV3 より素直に動く
src/content.js         全フレームに入る本体。最上位=切り抜き / 内側=引き伸ばし
src/content.css        クラスと自前 ID にしか作用しないので、OFF 時は無影響
src/background.js      タブ単位の ON/OFF 管理、全フレームへの配信、ズーム制御
src/popup.*            設定パネル
tools/inspect-frames.js  調査用コンソールスニペット (テキストのみ出力)
tools/fixture.html       罠を全部盛りにした検証用ページ
```
